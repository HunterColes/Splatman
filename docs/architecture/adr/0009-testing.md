# ADR 0009: test strategy

Status: accepted (2026-11-01, council #2)

All tests below are JVM unit tests (JUnit 5) in the pure modules, run by the gate through the
`testDebugUnitTest` alias (ADR 0001). GL and ARCore code is kept thin; their logic is tested through the pure
Kotlin it calls, and on the phone by the QA cards.

## Rules

- Fixtures are fixed: hand-computed values, or seeded random (`Random(42)`) for property checks, never time-seeded.
- Expected values in tests are computed independently of the code under test (by hand, in `Double`, or with a
  different formula), never by calling the same function.
- Tolerances are stated in the test, from the table below; a failing test is fixed, not loosened.
- Golden binary files live in `<module>/src/test/resources/golden/` with a `README.md` saying how each was made.

## What is tested, and to what tolerance

| Area | Tests (minimum) | Tolerance |
|---|---|---|
| Math | quaternion product against the Hamilton table; quat -> matrix for 90 degrees about each axis; inverse and compose of `Mat4`; `T_a_b * T_b_a = I` | 1e-6 (float) |
| Frames | ARCore identity pose: world point (0,0,-2) projects to (cx, cy); a point right/up of the axis lands right/up in the image (u > cx, v < cy); xyzw <-> wxyz round-trip; Cgl <-> Ccv twice = identity; projection matrix maps pixel edges to NDC +-1 and agrees with the pinhole formula on 1000 seeded points; W <-> F on positions, quaternions and every SH coefficient sign (the table in ADR 0003); `F(F(x)) = x` | 1e-5 px, 1e-6 elsewhere |
| SH | `eval` at degree 0-3 against hand-computed values for the 6 axis directions and one diagonal; constants C0..C3 to 15 digits; rotated-frame consistency: evaluating in W at `d` equals evaluating converted coefficients in F at `G d` | 1e-6 |
| Covariance | `Sigma = R S S^T R^T` is symmetric positive definite; isotropic splat at depth z with scale s projects to std `fx s / z` px; a splat elongated along X rotated 90 degrees about Z is elongated along v; the 0.3 px low-pass; behind-camera culling | 1e-4 relative |
| Sort | 16-bit counting sort orders 100k seeded depths back to front, equal to `sortedDescending` up to key quantisation; ties stable; all-equal depths; N = 0 and 1 | exact |
| Formats | PLY write -> read is bit-exact for degree 0, 1, 2, 3; header text matches a golden; reading a file with shuffled and extra properties; each bundled sample from #5 parses with its known count and degree; `.splat` round-trip within colour 1/255, rotation 1/128 (after renormalising), scale exact f32; SPZ round-trip within its quantisation steps and a golden file from the reference implementation | as stated |
| Packets | `SplatCloud` rejects mismatched array sizes; `transforms.json` write -> read equal; a newer `splatman_version` is rejected; unknown keys ignored; intrinsics `scaled()` | exact / 1e-6 |
| Capture logic | keyframe policy accepts and rejects on translation, rotation, tracking state and sharpness at the thresholds (just under, just over); voxel merge keeps one point per voxel and the cap | exact |
| Trainer | seed init: kNN scale on a regular grid equals the grid spacing; finite-difference gradient check of the backward pass for every parameter group on a 5-splat, 16x16 image scene in `Double` (relative error < 1e-3); a synthetic scene (render 8 views of a known 50-splat cloud, start from a perturbed cloud) reaches PSNR > 28 dB within 500 iterations | as stated |
| Renderer packing | packed texels decode back to centre, covariance (f16, 1e-3 relative) and colour; texture size for N splats | as stated |

## Golden data

- The CPU forward rasteriser (`splat-train/raster`) is the golden renderer: the synthetic scene's images are
  rendered by it and checked once by hand-computed pixels for a single splat (centre pixel alpha = opacity, colour).
- The tiny synthetic fixture from #5 (a handful of splats with known values, generated by a script) is the shared
  input for format and SH tests.
