# ADR 0011: crop box, inclusion rule and crop file layout

Status: accepted (epic #88, card #180). The splat-core, storage, renderer and UI cards of #88 share it. The card
asked for number 0010, which [ADR 0010](0010-gpu-training.md) (GPU training) already holds, so this is 0011.

## Context

A scan picks up floaters and background far from the subject. Epic #88 lets the user cut them away with one box
before exporting. Four cards build it (the box maths in splat-core, the files in library storage, live dimming in
the renderer, the Viewer UI); they must agree on one box shape, one rule for what is inside, and one layout on
disk that survives a crash at any point. Splatman is a scanner, not an editor: the crop tool stays one box.

## Decision

1. **Box type.** `CropBox(centre: Vec3, halfExtents: Vec3, rotation: Quat)` in splat-core package
   `com.huntercoles.splatman.splat.edit`, in world frame W ([ADR 0003](0003-coordinate-frames.md): +Y up, metres).
   `rotation` maps box-local axes to W and is unit. Reason: centre plus half extents plus a rotation is the
   smallest complete oriented box, and W is the frame every loaded cloud is already in.
2. **Inclusion rule.** A splat is kept when its centre `p` satisfies `|axis_k . (p - centre)| <= halfExtents_k`
   for k = x, y, z, where `axis_k` is the k-th column of `rotation`; the boundary is inclusive. Reason: testing
   the centre only is cheap, exact and matches what the user sees as the box; a splat's extent is soft (Gaussian)
   and has no single edge to test.
3. **Faces.** `enum class BoxFace { X_NEG, X_POS, Y_NEG, Y_POS, Z_NEG, Z_POS }`. Moving a face keeps the opposite
   face fixed (centre and half extent change together) and clamps the extent to at least 1 cm. Reason: dragging
   one side should not move the other; the clamp keeps the box from inverting or collapsing.
4. **The UI makes only W-aligned boxes** (rotation identity): no rotate handle, no transforms. The rotated case
   exists in the type and its tests only. Reason: the "not an editor" rule; six face handles are enough to cut
   floaters, and a later card can add rotation without changing the type or the files.
5. **Start box.** For every source (scan, import, sample) the first box is the per-axis 5th..95th percentile of
   splat centres (the central 90%). Reason: it ignores the far floaters a min/max box would include, and needs
   nothing but the cloud.
6. **Files of a scan.** The current splat stays `scans/<id>/splat.ply`. The first Apply keeps the original as
   `scans/<id>/splat.uncropped.ply`; later crops never overwrite it. Apply, in this order, so every crash point
   leaves a valid `splat.ply`:
   1. write the cropped cloud to `splat.ply.tmp` and fsync;
   2. only if no `splat.uncropped.ply` exists: copy `splat.ply` to `splat.uncropped.ply.tmp`, fsync, rename it
      to `splat.uncropped.ply`;
   3. rename `splat.ply.tmp` over `splat.ply`.

   Revert renames `splat.uncropped.ply` over `splat.ply`. Stale `*.tmp` files are deleted at the start of the next
   Apply. Reason: renames within one directory are atomic, so a reader sees either the old or the new file; every
   other module (export, library count, viewer) keeps reading `splat.ply` unchanged.
7. **Samples** are read-only assets: a cropped sample lives at `filesDir/sample-crops/<asset file name>`, the
   opener prefers it over the asset, and Revert deletes it. **Imports** are scans already (they are copied into app
   storage, [docs/design/screens/import.md](../../design/screens/import.md)), so rule 6 covers them.
8. **Library count.** After Apply or Revert on a scan, the Viewer calls
   `fun interface ScanChangeListener { suspend fun changed(scanId: String) }` (viewer-feature); app binds it to
   `ScanRepository.refresh(id)`, which recounts `splat.ply`. Reason: viewer-feature must not depend on
   library-feature (ADR 0001); app is where the two meet.
9. **Export needs no change.** After Apply or Revert the Viewer reloads its source, so the loaded cloud the Export
   sheet writes is the cropped one.
10. **Threads.** Live dimming of splats outside the box happens in the renderer's shader from a box uniform: no
    re-pack, no re-sort, so dragging a face stays at frame rate ([ADR 0006](0006-rendering.md)). The crop itself
    (`cropToBox`) runs on the default dispatcher, off the main and GL threads.

## Rejected

- **Rotate handles** and free transforms: an editor feature; they add a gizmo and its tests for little gain on
  floaters. The type allows rotation, so this can return later.
- **A brush** (paint splats away): many small edits, an undo history and per-splat selection state; the one box
  covers the epic's goal. Taken up by ADR 0014 (epic #322).
- **Storing the crop as a box applied at load** (keep `splat.ply` whole, save the box beside it): export, the
  library's splat count and every other reader would each have to re-crop, and a reader that forgets would show
  the uncropped cloud. Writing the cropped file once keeps every reader unchanged.

## Deferred

- **Fitting the start box to the capture subject**: the subject is not stored in the bundle today (splat-io has no
  field for it), so it is a separate proposal, not this epic.

## Consequences

- A cropped scan uses up to twice its splat's disk space (the kept original). Revert is a rename, so it is instant.
- `splat.uncropped.ply` is a new optional file in the capture bundle ([ADR 0007](0007-formats.md)).
- Crash safety rests on rename atomicity and fsync; storage tests cover each crash point of rule 6.
- Box tests (splat-core) cover the inclusive boundary, the rotated case, the face moves and the 1 cm clamp.
